# AI 利用ガイドライン

このリポジトリの開発で AI(Claude Code)を使うときに、渡してよい情報と渡さない情報の線引き、それを守る仕組みを定める。

## 1. 目的

AI は設計の壁打ち・実装・レビューに日常的に使う。一方で、AI に渡した情報は手元の外へ送信される。
このガイドラインは、**機密情報を AI に渡さないことを、ルールと仕組みの両方で守る**ためのもの。

求人の必須要件「機密情報を扱う際の AI 利用ガイドライン」に対応する。

## 2. AI に渡さない情報

| 種類 | 例 |
|---|---|
| ① 秘密情報 | API キー、トークン、パスワード、`.env`、`config/master.key`、`config/credentials/*.key`、GCP サービスアカウントの鍵ファイル |
| ② 本番データ | 本番 DB の中身、本番環境のログ(利用者の操作が記録されたもの) |
| ③ 個人情報 | 実在する人の名前、メールアドレス、Firebase Auth の実ユーザー情報 |
| ④ 本業クライアントの情報 | 業務委託先のコード、設計書、仕様、社内情報 |

④ は、このリポジトリに**持ち込まない**ことも含む。このポートフォリオのコードと設計は、すべてこのリポジトリのために書いたものに限る。

## 3. 渡してよい情報

- このリポジトリのコードと文書(公開前提で書いているもの)
- ダミーデータ(架空の名前、`example.com` のメールアドレスなど)
- 秘密情報を伏せたエラーメッセージやログ

## 4. 仕組みで守る

ルールは忘れるので、守れる部分は仕組みにする。

| 層 | 何を防ぐか | 設定場所 |
|---|---|---|
| Claude Code の deny | Claude Code が秘密情報のファイルを Read ツールで読むこと | [.claude/settings.json](../.claude/settings.json) |
| `.gitignore` | 秘密情報のファイルがコミットされること | [.gitignore](../.gitignore) |
| GitHub の secret scanning / push protection | 鍵などが含まれたコミットの push(`.gitignore` をすり抜けた場合の最後の砦) | GitHub のリポジトリ設定(有効化予定) |

deny と `.gitignore` で対象にしているファイルは次のとおり。

- `.env`、`.env.*`(`.gitignore` では見本の `.env.example` だけコミット可)
- `**/config/master.key`、`**/config/credentials/*.key`
- `*service-account*.json`(GCP のサービスアカウント鍵は、この名前を含めて保存する)

あわせて、次の方針をとる。

- CI で使う秘密情報は GitHub Secrets に置く。
- GitHub Actions から GCP への認証は、鍵ファイルを使わない Workload Identity 連携にする。鍵ファイルを作らなければ、漏れることもない。
- 本番の秘密情報(`RAILS_MASTER_KEY`、DB のパスワードなど)は Secret Manager に置き、Cloud Run から参照する。

## 5. 仕組みの限界と運用ルール

仕組みで防げない経路がある。

- **deny が止めるのは Read ツールだけ**。Claude Code が Bash で `cat .env` などを実行する経路は防げない。
- **ログやエラーメッセージの中に、秘密情報が混ざることがある**。例:接続文字列に含まれる DB のパスワード、リクエストヘッダーの認証トークン。

そのため、次を運用ルールとする。

- 秘密情報を表示するコマンド(`cat .env`、`printenv`、`rails credentials:show` など)を AI に実行させない。AI が実行しようとしたら、許可せずに止める。
- ログやエラーを AI に貼る前に、秘密情報が含まれていないか見て、含まれていれば伏せる。
- 秘密情報を含む作業(鍵の発行、Secret Manager への登録など)は、AI を通さず自分の手で行う。

## 6. 万一渡した・コミットしたとき

**最初にやるのは、鍵の無効化と再発行**。履歴から消すのはその後でよい。

1. 漏れた鍵・トークン・パスワードを無効化し、新しいものを発行する。
2. 新しいものを、正しい保存場所(Secret Manager、GitHub Secrets など)に登録する。
3. コミットしてしまった場合は、Git の履歴から削除する。
4. 何が・いつ・どこまで漏れたかと、再発防止策を `docs/` に記録する。

このリポジトリは Public なので、一度 push された鍵は自動で収集されている前提で動く。履歴を消しても、既に取得された鍵は使えてしまうため、無効化が先になる。

## 7. 見直し

新しい種類の秘密情報が増えたら(例:外部 API のキー)、次の 3 つを同時に更新する。

- [.claude/settings.json](../.claude/settings.json) の deny
- [.gitignore](../.gitignore)
- このガイドライン

AI への作業ルール全般は [CLAUDE.md](../CLAUDE.md) にある。
