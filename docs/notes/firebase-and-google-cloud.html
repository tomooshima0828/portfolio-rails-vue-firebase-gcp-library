Firebase と Google Cloud の関係

このアプリは、Firebase のコンソールと Google Cloud のコンソールの両方で設定を行います。2つは別のサービスに見えますが、中身は同じ1つのプロジェクトです。このノートは、2つの関係と、このアプリでどちらの機能をどう使っているかを、1枚にまとめたものです。特定の Issue のためではなく、フェーズ2以降の作業で迷ったときに戻る地図として使います。

1出発点:なぜ関係を知っておくと迷わないのか

このアプリの本番環境は、Issue #29 で作ったプロジェクト knowledge-library-prod の中にあります。ところが、作業によって開くコンソールが違います。

  • Issue #29 では、Firebase のコンソールでプロジェクトを作り、Blaze プランに上げた
  • Issue #30・#31 では、Google Cloud のコンソールで Cloud Run と Cloud SQL を作った
  • Issue #32 では、Firebase のコンソールで Firebase Auth を設定し、Firebase Hosting にデプロイする

そのため、「Firebase のプロジェクトと Google Cloud のプロジェクトは別のものなのか」「どの機能をどちらで操作するのか」「料金はどちらにかかるのか」で迷いやすくなります。答えは1つで、Firebase のプロジェクトは、Firebase の機能を足した Google Cloud のプロジェクトそのもの です。プロジェクト ID も、課金も、権限(IAM)も、1つを共有しています。

21つのプロジェクトと、2つのコンソール

Google Cloud のプロジェクトは、機能(Cloud Run、Firestore など)と、共通の仕組み(権限、課金、API の有効化)を入れる箱です。この箱に「Firebase を使う」という印を付けると、Firebase のコンソールからも開けるようになります。Issue #29 で Firebase のコンソールからプロジェクトを作ったので、knowledge-library-prod には、初めからこの印(firebase=enabled のラベル)が付いています。

Firebase の料金プランと課金の関係:Firebase の「Spark プラン」(無料)と「Blaze プラン」(従量課金)は、プロジェクトに Google Cloud の請求先アカウントをつないでいるかどうかの違いです。Issue #29 で Blaze に上げたことは、Google Cloud の側から見ると、請求先アカウントをつないだことと同じです。そのため、Firebase の機能の料金も、Cloud Run や Cloud SQL の料金も、同じ請求先アカウントに請求され、同じ予算アラート(月 3,000円)で見張られます。

3ブラウザから直接呼ぶ機能と、Rails から使う機能

Firebase の機能と Google Cloud の機能は、「誰が呼ぶか」で分けると覚えやすくなります。Firebase の機能の多くは、ブラウザの JavaScript から、Firebase の SDK(Firebase が配るライブラリ)を使って直接呼ぶように作られています。Google Cloud の機能は、サーバー(このアプリでは Rails)から使うものが中心です。

この分かれ方には理由があります。Firebase の機能は、サーバーを書かずにアプリを作れるように、ブラウザから安全に呼べる仕組み(Firebase Auth の ID トークン、Firestore のセキュリティルール)を持っています。一方、Cloud SQL のようなデータベースは、ブラウザから直接触らせず、サーバーが間に立って中身を確かめてから読み書きします。このアプリは、記事などのデータを Rails(Cloud SQL)に置き、リアルタイムに反映したいコメントとリアクションだけを Firestore に置く、と決めています(architecture.md)。

例外:Firebase Hosting は SDK で呼ばない。ブラウザは、普通の Web サイトと同じように、URL を開いて Firebase Hosting からファイルをもらいます。図2 では「ブラウザが直接やりとりする」という意味で、左の列に入れています。

4Firebase の機能と、Google Cloud 側の中身

Firebase の機能の多くは、Google Cloud の機能に、ブラウザから使いやすい SDK と、Firebase のコンソールの画面をかぶせたものです。そのため、同じものが、Google Cloud のコンソールからも見えます。

Firebase の機能Google Cloud 側の中身Google Cloud のコンソールでの見え方
Firebase Authentication(Firebase Auth)Identity Platform と同じ仕組み。API は Identity Toolkit API「API とサービス」の一覧に Identity Toolkit API として出る。設定は Firebase のコンソールで行う
Firebase HostingFirebase 独自。Google Cloud に同じ名前の製品はない「API とサービス」の一覧に Firebase Hosting API として出るだけ。設定は Firebase のコンソールと firebase.json で行う
Cloud FirestoreGoogle Cloud の Firestore そのもの「Firestore」の画面で、同じデータベースが見える
Cloud Storage for FirebaseGoogle Cloud の Cloud Storage のバケット「Cloud Storage」の画面で、同じバケットが見える
Cloud Functions for FirebaseCloud Run functions(第2世代は Cloud Run の上で動く)「Cloud Run」の画面に出る
Blaze プランプロジェクトに、Cloud Billing の請求先アカウントをつないだ状態「お支払い」の画面
プロジェクトのメンバーIAM(誰に、どの役割を付けるか)「IAM と管理」の画面

反対に、Cloud Run、Cloud SQL、Secret Manager、Artifact Registry には、Firebase の名前の付いた版はありません。Google Cloud のコンソールで操作します。

確かめていないこと:Firebase Auth と Identity Platform の関係は、Google の文書の説明によるものです。このプロジェクトでは、Firebase Auth を Identity Platform に切り替える(アップグレードする)操作はしていません。Identity Toolkit API が有効になっていることだけを、gcloud で確かめました(2026-11-16)。

5このアプリで使う機能と、使わない機能

機能使わない理由
Cloud Storage for Firebase画像は、Rails の Active Storage から、Google Cloud の Cloud Storage に置く予定。ブラウザから直接ファイルを置く形にはしない
Cloud Functions for Firebaseサーバーの処理は、Cloud Run の Rails で書く
Realtime Databaseリアルタイムに反映するデータは、Firestore に置く(architecture.md)
Analytics、Remote Config などこのアプリの目的に要らない。Issue #29 でプロジェクトを作るときに、Google アナリティクスは使わないと決めた

Firebase の機能の API の一部(Remote Config など)は、使っていなくても、Firebase を足したときに自動で有効になっています。有効になっているだけでは料金はかかりません。

6どちらのコンソールで操作するか

このアプリの作業で、どちらのコンソールを開くかの一覧です。手順は production-setup.md にあります。

作業開くコンソールIssue
プロジェクトを作る、Blaze プランに上げるFirebase のコンソールIssue #29
予算アラートを直すGoogle Cloud のコンソール(「お支払い」)Issue #29
API を有効にする、IAM の権限を付けるGoogle Cloud のコンソールIssue #30・#31
Cloud Run、Artifact Registry、Secret Manager、Cloud SQLGoogle Cloud のコンソールIssue #30・#31
Google ログインを有効にする、ウェブアプリを登録するFirebase のコンソール(「Authentication」「プロジェクトの設定」)Issue #32
Vue のファイルをデプロイするコンソールではなく、手元のターミナルの Firebase CLI(firebase deploy)Issue #32
Firestore のデータベースとセキュリティルールFirebase のコンソール(ルールは Firebase CLI でもデプロイできる)フェーズ4

迷ったら、「名前に Firebase が付く機能(または Firestore)なら Firebase のコンソール、それ以外は Google Cloud のコンソール」と覚えておけば、ほぼ合います。権限と課金は、どの機能のものでも Google Cloud のコンソールで扱います。

開発用のプロジェクトとの違い:開発用の knowledge-library-dev も、同じ形の Google Cloud のプロジェクトです。ただ、Spark プラン(請求先アカウントをつないでいない)のままで、使っているのは Firebase Auth だけです。Cloud Run や Cloud SQL は請求先アカウントがないと使えないので、本番用にだけあります(ADR 0005)。
