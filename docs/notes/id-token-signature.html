ID トークンの署名

Rails は、Vue から届いた ID トークンが Google の発行したもので、途中で書き換えられていないことを、署名で確かめます。このページでは、その確かめ方を図で順に追います。

先に結論です。Rails は、2つの道具で2つの値を作り、それを比べます。

① ヘッダーとペイロードから計算したハッシュ と ② 署名を公開鍵で開いて出てきたハッシュ が同じなら 本物

1先に知っておく2つの道具

署名の仕組みは、ハッシュと鍵のペアの2つの道具でできています。2つは役割が違います。ハッシュは鍵を使いません。鍵のペアは、ハッシュに署名するために使います。

道具1

ハッシュ(SHA-256)

どんなに長い文字列からでも、決まった長さの短い値を作る計算です。文字列の指紋のようなものです。

ヘッダー.ペイロード
(sub が Xk3p…)275675c7…
ヘッダー.ペイロード
(sub が Xk3q…、1文字だけ違う)f9977bc0…
  • 同じ文字列なら、誰が計算しても同じ値になる
  • 1文字違うだけで、まったく違う値になる
  • 鍵は使わない。誰でも計算できる

道具2

鍵のペア(RSA)

秘密鍵と公開鍵は、2つで1組です。kid は、この1組につけた名前です。

秘密鍵Google だけが持つ。ハッシュから署名を作る
公開鍵JWKS の URL から誰でも取れる。署名を開く
  • 秘密鍵で作った署名を、対になる公開鍵で開くと、署名したときのハッシュが出てくる
  • 別の秘密鍵で作った署名からは、正しいハッシュは出てこない
  • 公開鍵から秘密鍵を割り出すことはできない

ハッシュの値は、このページの例のヘッダーとペイロードを実際に SHA-256 で計算した結果の、先頭8文字です。

2Google が署名を作る

ログインのとき、Google(Firebase Authentication)が ID トークンを作ります。

  1. Google が、ヘッダーとペイロードを . でつないだ文字列を作る
  2. Google が、その文字列から SHA-256 でハッシュを作る
  3. Google が、そのハッシュに秘密鍵で署名する
  4. Google が、署名を後ろにつなぎ、ID トークンとして Vue に渡す

3Rails が署名を確かめる

Vue からトークンが届くと、Rails(jwt gem)はトークンを3つに分け、2つの道筋で値を作ります。

  1. Rails が、受け取ったヘッダーとペイロードから、Google と同じ手順(SHA-256)でハッシュ ① を計算する。ここでは鍵を使わない
  2. Rails が、ヘッダーの kid を見て、同じ kid の公開鍵を JWKS から選ぶ
  3. Rails が、その公開鍵で署名を開き、Google が署名したときのハッシュ ② を取り出す
  4. Rails が、① と ② を比べる。同じなら、このトークンは本物で、書き換えられていない

① は「今、手元にある中身」のハッシュです。② は「Google が署名したときの中身」のハッシュです。2つが同じなら、Google が署名してから中身が変わっていないと言えます。しかも ② を取り出せるのは、Google の秘密鍵で作った署名だけです。

4確かめに失敗する2つの場合

偽物を作ろうとする人には、主に2つのやり方があります。どちらも、① と ② が一致しなくなります。

A. 本物のトークンのペイロードを書き換える

B. 自分の秘密鍵で署名した偽物を作る

5このプロジェクトのコードとの対応

図2の比較は、JWT.decode の中で jwt gem がまとめて行います。実際の計算は OpenSSL が担当します。私たちのコードで、ハッシュを計算することはありません。

payload, _header = JWT.decode(
  token,
  nil,
  true,                                 # 署名を確かめる → jwt gem が図2の比較を行う
  algorithms: [ "RS256" ],              # ハッシュは SHA-256、署名は RSA の方式だけを認める
  jwks: self.class.method(:fetch_jwks), # kid に合う公開鍵を選ぶための一覧
  ...
)

図2(一致)「有効な ID トークンの場合」の3件
図3(書き換え)専用のテストはありません。図4と同じ署名の確認で防いでいます
図4(別の鍵)「別の鍵で署名されている場合」(55行目)
図2の比較そのものを飛ばす攻撃「HS256」と「none」の2件。algorithms: ["RS256"] で防いでいる

「公開鍵で署名を開くとハッシュが出てくる」は、RS256(RSA の PKCS#1 v1.5 という方式)の確認の仕組みを、分かりやすく言い換えたものです。実際には、ハッシュの前に方式を示す決まった値もいっしょに出てきます。仕組みを理解するうえでは、この言い換えで十分です。

6確認用の問い

  1. ハッシュ ① を計算するとき、Rails はどの鍵を使いますか。図2の左の道筋です。
  2. ペイロードを書き換えた人が、署名も作り直せないのはなぜですか。図3の説明です。
  3. 攻撃者が kid を本物と同じにしても、確かめに失敗するのはなぜですか。図4の説明です。
