# 本番の Google Cloud プロジェクトを用意し、予算アラートを設定する

Issue: #29

## 目的

フェーズ2で本番の Rails・DB・Vue を置く土台を用意する。開発用とは別のプロジェクトを作って課金を有効にし、想定外の課金に気づけるよう予算アラートを設定する。

このタスクでは、まだ何も動かさないため、料金はかからない。課金が始まるのは #31(Cloud SQL)から。

## やること

作業はオーナーが Firebase と Google Cloud のコンソールで行う。手順は Claude が出し、結果を一緒に確かめる。

- 本番用のプロジェクトを、Firebase のコンソールから作る。Google Cloud のプロジェクトと Firebase が一度にできる
- 請求先アカウント(Cloud Billing アカウント)を新しく作り、本番用のプロジェクトに紐づける。Firebase のプランを Blaze(従量課金)に上げることに当たる
- 本番用のプロジェクトに、月 3,000円の予算アラートを設定する
- 開発用と本番用のプロジェクトを分ける判断を ADR に残す
- 本番環境の作り方を書く手順書 `docs/production-setup.md` を作り、このタスクで行った手順を書く。#30 以降のタスクでも書き足す

## やらないこと

- API の有効化、サービスアカウントの作成(#30 で、使うときに行う)
- 本番の Firebase Authentication、Firebase Hosting の設定(#32)
- 予算を超えたときに課金を自動で止める仕組み(予算アラートからの通知を受けて、課金を外す処理を動かすもの)。月 3,000円の規模では、メールを見て手で止めれば足りる
- 組織(Organization)やフォルダの作成。個人のアカウントで作る
- Terraform などでの構成のコード化(README の通り、余力があれば)

### 判断したこと

- **プロジェクトは Firebase のコンソールから作る**。Google Cloud のコンソールで作ってから Firebase を足すこともできるが、Firebase のコンソールからなら一度で済み、開発用のプロジェクトを作ったとき(README の「初回の準備」)と同じ手順になる。途中で聞かれる Gemini と Google アナリティクスは、開発用と同じく使わない
- **プロジェクト ID は `knowledge-library-prod` にする**。ID は後から変えられず、世界で一意なので、使われていれば末尾に数字が付いたものを受け入れる。表示名は `knowledge-library-prod` とそろえる
- **予算アラートの対象は、本番用のプロジェクトだけにする**。請求先アカウント全体にすると、今後ほかのプロジェクトを紐づけたときに、通知の原因がどのプロジェクトか分からなくなる
- **通知の段階は、実際の費用の 50%・90%・100% と、予測の 100%**。前の3つはコンソールの既定。予測の通知を足すと、月の途中で「このままだと超える」と分かる。Cloud SQL は月 1,500円前後の見込みなので、#31 で Cloud SQL を動かし始めると、50% の通知が毎月来る可能性がある。そうなったら、そのときに金額か段階を見直す
- **請求先アカウントの通貨は日本円にする**。通貨は作った後に変えられない。予算の金額も、この通貨で指定する
- **無料トライアルのクレジットが付く場合も、予算はクレジットを引く前の金額で見る**。クレジットを引いた後の金額で見ると、トライアルの間は費用が 0円に見えて通知が来ず、トライアルが終わった後の本当の費用に気づけない
- **予算アラートは、課金を止めない**。通知を送るだけで、超えても課金は続く。止めるのは、通知を見たオーナーが手で行う(Cloud SQL を止める・削除する。docs/principles.md の通り)
